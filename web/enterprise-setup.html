OPERATOR SETUP

Real email verification & company onboarding

Configure delivery first, then verify your real company account.

1. Configure SMTP in Supabase

The operator must configure their own SMTP provider. This project has not been given SMTP credentials. The default Supabase mail service is restricted and is not a production company-email delivery service.

  1. Open your existing Supabase project → Authentication → Email / SMTP settings.
  2. Enter the verified sender address, SMTP host/port, username and password directly in Supabase.
  3. Verify the sender domain and configure SPF/DKIM as your mail provider requires.
  4. Set delivery and authentication rate limits appropriate to your provider.

Keep SMTP secrets out of the repository, website and user messages.

Official SMTP setup guide

2. Enable actual OTP codes

Authentication → Email Templates → Magic Link: include {{ .Token }} in the email body. This variable produces the real verification code; do not replace it with a fixed test code. Configure a short expiry such as ten minutes and test your real inbox.

Official email OTP guide

3. Register and create your company

  1. Install the newest Trial or Full release. First launch shows Register / Sign in.
  2. Register with your full name and company-domain email.
  3. Request the code, check your inbox/spam, then enter that code in the CRM.
  4. Company accounts → Create workspace → enter company name. If the domain already belongs to a workspace, accept an administrator invitation instead.

Mailbox verification proves email access. Company/domain control remains pending until the owner adds the displayed DNS TXT record and presses Verify DNS domain control in Company accounts. A new workspace receives a clearly labelled seven-day hackathon evaluation.

4. Add members and enable protection

  1. Owner/admin creates an invitation for the exact company email and shares the code securely.
  2. The recipient verifies their own email and accepts the invitation. Invitations are not automatically emailed.
  3. On each Full device, install the newest browser companion, create/enter a pairing code, grant individual website permissions and accept monitoring consent.
  4. Admin → Company accounts → Risk threshold & browser protection. Enable the hold and choose a threshold.
  5. Test a synthetic credential pattern. An intercepted submission should be held and appear in the company activity log.

Raw prompts and file bytes are not uploaded. Optional redacted previews require separate consent. Browser controls and provider websites change, so real provider-page testing is required. This does not trace provider internals or enforce every app/network request.

5. Paid access and alerts

A Full download is not proof of a ₹90,000 payment. The operator verifies the real merchant/bank transaction before setting the company's server-side paid license. Online checkout and webhook verification are not configured.

Phone push uses your authenticated ntfy topic and requires its own setup. Local notifications/reporting run while the CRM is open. Native packages are unsigned; production signing and security review remain required.
